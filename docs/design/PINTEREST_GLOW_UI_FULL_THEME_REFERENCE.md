# Pinterest Glow UI Full Theme Reference

## Evidence boundary

The supplied Pinterest search results were opened in a logged-in browser. The visible result grid shows: a dark background; isolated high-contrast light sources; one rounded “Home” control with a narrow rainbow edge; color studies for purple, orange, pink, green, and blue; a black rounded “Let me glow” control with a slim halo; a purple `NEON GLOW in Figma` panel with three small glowing icons; a translucent mobile dashboard card floating over blue-violet light trails; and partially visible dark mobile/status screens. Search tags include Neon, Animation, Blue, Ambient, Dark, Soft, Inner, Button, Elements, Edge, Futuristic, Purple, Gradient, Card, Glass, Mobile, Subtle, Green, Space, and Dark mode.

## Glow UI system translation

| Observed signal | Telegram Drive translation | Guardrail |
|---|---|---|
| Dark field with isolated source lights | Keep the existing dark Mission Control field and treat each route’s factual primary action as its single bright source. | Light mode remains supported and uses opaque M3 surfaces. |
| Narrow chromatic rim on a rounded control | Use a semantic cobalt/teal focus rim on existing primary actions and selected destinations/navigation. | Do not create new actions or use a glow as the only selection/status cue. |
| Small, contained icon halos | Add a small status halo around real connection, notification, and upload-status icons. | Halo appears only for actual state and does not pulse when Android motion is disabled. |
| Floating glass mobile/dashboard card | Use bounded translucent M3 cards, one dominant upload hero, and quiet secondary panels. | Do not introduce balances, agents, media feeds, rewards, or mock queue activity. |
| Color-study variety | Reserve cobalt for primary/action, teal for confirmed completion, amber/error semantic roles, and purple/blue-violet only as decorative atmosphere. | Paired `on-*` contrast roles, label/icon state cues, and error recovery remain mandatory. |
| Soft inner/edge glow | Use clipped low-opacity inner reflection and endpoint glow on the real upload fraction. | Never make decorative motion alter progress, speed, ETA, completion, or task ordering. |

## Motion language

Route entry stays finite and orientation-focused. Primary actions have a tactile press response; state changes use short interruptible color/content transitions; upload endpoint light is derived from real fraction and `UPLOADING`; connection/notification halo responds only to genuine state; background Aurora remains slow and limited to focal surfaces. Infinite motion is not used on large lists, forms, history, or error recovery and all nonessential motion is removed under Android animator-scale reduction.

## Non-transfers

The visual search includes Web3, generic dashboard, color-study, and home-button material. It does not authorize cryptocurrency, gaming, smart-home, AI-agent, balance, or fictional dashboard content in the uploader.
